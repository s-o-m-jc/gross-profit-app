最終更新: 2026-11-13(コミット `a011993` の時点)。新しいセッション・別のClaudeが最初に読むための要約です。
詳細な経緯・調査結果はリポジトリ直下の `CLAUDE.md`(自動で読み込まれる)にあり、この資料は各節への道案内を兼ねます。

## 1. アプリの目的

- 四国人材・大阪人材・松山人材の3拠点(はまさんの会社。人材派遣業)の**月次の粗利・経理の資料**を作るWebアプリ。
- いまは各拠点の経理がExcel(勤怠明細票・派遣明細・契約別売上実績表など)でスタナビ(派遣管理システム)の出力を手作業で加工している。
  **最終目標は、この手作業をスタナビのCSVの直接取込に置き換えること**。
- **許容するずれは、消費税の端数の1円だけ**。それ以外のずれは、アプリかExcelのどちらかの誤りとして原因を突き止める。
- 対象は粗利だけでなく全部: 月次粗利明細一覧・月次サマリ・スタッフ給与明細(勤怠・控除の内訳)・監査アラート
  (社保差異・交通費不一致・支払額の不一致・単価の急変など)・決算期(年間)集計とグラフ・紹介手数料・駐車場代・立替金・交通費(税抜)。
- 本番URL: https://gross-profit-app-oqpi.vercel.app (これ以外のURLを案内しない。理由は `CLAUDE.md`「本番環境のURL」)。
- 構成: React + Vite + TypeScript、Supabase(DB・認証)、Vercel(masterへのpushで自動デプロイ)。データは `monthly_data` テーブルに
  会社×対象月の1行ずつ、`state`(jsonb)に `billingRows / payrollRows / invoiceRows / referralFeeRows / …` を持つ(全120行: 大阪38・松山36・四国46ヶ月)。

## 3. CSVの仕様(スタナビの出力)

| 番号 | 名前 | 中身 | アプリでの使い道 |
|---|---|---|---|
| ① | 給与計算書印刷CSV(全項目ON、**76列**) | スタッフ×月で1行。勤怠・各手当・交通費1/交通費2(45列目)・立替金(49列目)・総支給額(AY)・雇用保険対象額(AZ、見出しが空のことあり)・本人負担の健保/介護/年金/雇用保険・社保合計・所得税・住民税・総控除額・差引支給額 | `parsePayrollCsv`。給与明細の表示、雇保(会社負担)の計算、社保差異・支払額の不一致のチェック、交通費の突合 |
| ② | 請求支払一覧表印刷CSV(17列) | 契約(受注)×月で1行。請求No・クライアント・請求先部署・スタッフ・受注・**請求額・支払額・社保負担額(会社負担)**・粗利額・有給使用日数・担当者 | `parseBillingCsv`。**粗利の計算の元**(粗利 = 請求額 − 支払額 − 社保負担額 − 退職金) |
| ③ | 請求書印刷CSV | 請求書の明細。時間内－単価、交通費－金額(課税・税抜)、課税1〜5、**非課税1〜5－金額**、小計、備考1〜3、受注番号 | `parseInvoicePrintCsv`。請求＠、請求交通費、非課税分・立替金の判定 |

- 3拠点とも同じスタナビの出力。見出しの文字だけ違う(四国の②は「ク番号/ス番号/有休/担当」、①の手当の枠の名前、空の見出しなど)。
  シートに貼られたものは、四国=勤怠明細票「未払計上表」(10行目見出し)、松山=派遣明細「未払計上表」、大阪=「給与一覧（スタナビ）」。
  「給与一覧」というスタナビの出力は無い(大阪の担当者が付けたシート名)。
- ②には交通費・立替金・相殺・紹介手数料・単価の列が無い。立替金・相殺・休業手当は請求額・支払額に混ざって入っている(→4章)。
- **賃金台帳・給与明細は使わない**: 給与計算書印刷CSVが賃金台帳CSVの金額項目をすべて含み、交通費1・2・立替金・駐車場手当など賃金台帳に無い項目もある。
  賃金台帳CSVは法定の賃金台帳(性別・賃金計算期間が要る)をExcelで作るためのもので、アプリには不要(`CLAUDE.md`「スタナビCSVの列名の違い…」)。
  給与明細(個人向けの帳票)は一覧のデータにならないため使わない(※これは推定。はまさんに明示的に確認した記録は無い)。

## 4. 業務ルール(はまさんに確認済み)

| 項目 | ルール | 実装 |
|---|---|---|
| 粗利 | 請求額 − 支払額(②) − 社保負担額(②、会社負担) − 退職金。雇用保険・駐車場代・交通費は別に引かない(支払額・社保負担額に含まれる) | `calculator.ts` |
| 消費税 | 税込 = (請求額 − 非課税分) × 1.1 + 非課税分。原価(給与・社保など)は不課税で税を掛けない | `toIncTax` |
| 交通費(請求する) | 税込とみなして割り戻した額を他の請求額と合算し、消費税を計算。請求書の課税欄に税抜で入っている | 請求交通費は課税 |
| 交通費(自社負担) | 請求せず、スタッフに支払うだけ。請求額に無いので消費税の対象外。交通費を請求しない契約は正常(「交通費込みの単価」ではない) | `NOT_BILLED_CONTRACT` |
| 交通費(税抜)の表示 | 行ごとの値の自動集計。大阪・松山=請求交通費、四国=給与の支給交通費(交通費1+2)。手入力はデータの無い月だけ | `transportExTaxDisplay.ts` |
| 立替金 | **売上に含めない**(税抜・税込とも)。派遣先に請求しスタッフに支払った立替金は、売上と支払の両方から除く(粗利は不変)。消費税は掛けない | `BillingRow.reimbursementAmount` |
| 寸志(大阪) | 立替金と同じく売上・支払の両方から除く | 同上 |
| 休業手当・休業分補償 | 売上に含めるが非課税(税を掛けない)。手入力の休業分補償も非課税 | 非課税分 |
| 相殺(駐車料・制服代など) | 請求書の非課税欄にマイナスで入る。四国の経理は売上に足し戻して地代家賃で処理。大阪・松山のDBは非課税の売上(マイナス)のまま(**拠点で揃っていない→5章の保留**) | 非課税分 |
| 駐車場手当 | スタッフへの手当で、総支給額=支払額に含まれる。粗利から別に引かない(以前は二重に引いていた)。表示上は給与総額から除き社保他小計に出す | `parkingFeeShare` |
| 紹介手数料 | 粗利に入れない。総売上(派遣売上+紹介手数料)には入れる。手入力(`ReferralFeeRow`)。四国は実績CSVの紹介手数料の請求書で派遣売上から付け替え | `referralFeeRows` |
| 雇保(会社負担) | 雇用保険対象額 × 事業主料率(〜2025-03 0.95%、2025-04〜 0.9%)。社保負担額の内数で、粗利では別に引かない(表示用) | `employmentInsuranceRates.ts` |
| 年齢・性別など | 点数・判定に使わない(このアプリには該当機能なし) | — |

## 7. 進め方のルール

- **本番DBを変える前に**: (1)全テーブルをタイムスタンプ付きでバックアップ(リポジトリ外)し件数を照合、(2)対象行の一覧と変更内容をはまさんに示して**承認を得る**、
  (3)書き込む直前にバックアップとDBが一致するか再確認、(4)対象の項目だけを書き込み、(5)全行を突き合わせて対象外が不変であることと、粗利の変化が想定どおりかを確認。
  jsonbはキーの並びが変わるので、照合はキー順を無視する。
- **実ファイルを直接確認する**: 推測で書かない。元のExcel・スタナビのCSV・本番DB(バックアップ)を開いて1円単位で突き合わせる。記録と食い違えば実データを正とし、記録を直す。
- **service_roleキー**: DB補正のときだけ `.env.local` に `SUPABASE_SERVICE_ROLE_KEY` として一時的に入れてもらう。作業後は消し、Supabaseで再発行(ローテーション)してもらう。
  Vercelの環境変数や通常の実行には入れない。値を画面・ログ・コミットに出さない。
- **Supabaseの無料プランは、しばらくアクセスが無いと一時停止する**(はまさんの認識。正確な条件はSupabaseの案内で確認)。停止中はアプリもスクリプトも動かないので、
  ダッシュボードで再開してもらう。
- **一括削除の前**: 古い `npm run dev` を全部止め、localhost のタブを閉じる(サンプルデータが書き戻された事故の再発防止。`CLAUDE.md`)。
- **役割分担**: はまさん⇔クラウドのClaude(調査・指示書)⇔ローカルのClaude Code(実装・commit・push・DB作業)。ロジック・データ整合性の不具合は、
  クラウド側の調査結果を受けてローカル側が独自に設計・実装する(二重チェック)。
- **Git**: リポジトリ `s-o-m-jc/gross-profit-app`、SSHで `git push`(ghのアカウント切替は不要)。masterへのpushで本番に自動デプロイ。
  デプロイの確認は `curl -s https://gross-profit-app-oqpi.vercel.app/version.json` の commit。
- **テスト**: `npm test`(tsx --test)、`npx tsc --noEmit`、`npm run build`。データの補正をしたら、その内容を `CLAUDE.md` に日付・件数・バックアップのパスと一緒に記録する。
- 報告は、はまさんにやさしい言葉で。複雑な調査ではOpus、通常はSonnetを提案(`CLAUDE.md`)。
